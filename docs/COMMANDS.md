## 2. 匹配规则（三件事决定是否触发）

```
① 斜杠前缀：消息以 / 或 ／ 开头   ← AstrBot 会剥掉前缀，插件读原始消息判断
② 或者喊名字：消息里出现 阿灰 / 小灰 / 灰狼
③ 然后正则命中某条规则
```

- **不带斜杠、也不喊名字 → 不触发**，消息正常走聊天
- **带斜杠但没命中任何规则 → 不触发，且不会进大模型**（直接丢弃）
- 城市名会被提取出来（`CITY_NAMES` 里逐个匹配），用于城市类查询

## 4.5 下次 vs 近期（语义区分）

```
/下次展           → 只出一场（最近的）
/江苏下次展       → 只出一场（江苏最近的）
/近期展           → 10 场即将举办 + 2 场已结束
/江苏近期展       → 江苏的展会列表（最多 6 场）
/江苏有什么展     → 同上
```

判断依据：句子里有没有「下次 / 下一」——有就是单场，否则是列表。

## 5. 每个功能输出什么

卡片分两类：

**单展会卡**（`/下次展`、城市查询）—— 顶部宣传图 + 大字倒计时 + 场地/主办，
城市查询是同一版式去掉宣传图，用列表形式展示多场。

**多展会卡**（`/近期展`）—— 圆角卡片，每场一张，卡间留缝：

```
近期展会
已结束 2 场 · 即将举办 10 场

已结束
┌──────────────────────────────┐
│ 18 天前  魔法万圣夜小聚        │  ← 背景是压灰的宣传图
│          2026-10-31 ~ 10-31   │
│          长沙 · 长沙德盛道夫酒店 │
└──────────────────────────────┘

即将举办
┌──────────────────────────────┐
│  9 天    海洋之泪              │
│          2026-11-27 ~ 11-29   │
│          嘉兴 · 太平洋大酒店    │
└──────────────────────────────┘
```

版式规则：

- **已结束的排在前面**（最近结束的先），然后即将举办
- 每张卡片 **300px 高**，左右各留 24px 边距，卡间 **20px 缝隙**，圆角 22px
- **未开始的保留原色**（只压 18% 亮度防过曝），**已结束的整张转灰**
- 文字不靠遮罩压暗，而是给文字加**柔和阴影**（四向 + 右下偏移各铺一层，模糊 2px），
  这样背景颜色不会被盖掉
- 卡片底部最后 45% 轻微过渡到卡片底色，收尾自然
- 左边大字：即将举办橙色「N 天」，已结束灰色「N 天前」
- 右边三行：**全名** / 日期 / **城市 · 场馆**（城市取 `region`，场馆取 `placeName`）
- **全名 = 主办 + 名称**：数据里只有 `name='双澜遗珠'`、`org='绒萌世界'`，
  显示时要拼成「绒萌世界双澜遗珠」；若 `name` 已包含主办则不重复拼（`_full_name()`）
- 最多 2 场已结束 + 10 场即将举办

| key | 输出 | 缓存 |
|---|---|---|
| `next` | 单展会卡：宣传图 + 天数 + 日期 + 场地 + 主办 + 之后三场 | 当天 |
| `recent` | 多展会卡：10 场即将举办 + 2 场刚结束 | 当天 |
| `city_list` | 同 `recent` | 当天 |
| `city_next` | 该城市/省份即将举办的展会（最多 6 场，**带宣传图卡片**） | 当天 + 城市 |
| `city_past` | 该城市/省份已举办的展会（最多 6 场，灰色卡片） | 当天 + 城市 |
| `fortune` | 人品卡：分数 + 等级 + 进度条 + 今日提示（900×740，紧凑版） | 当天 + 用户 + 昵称 |
| `stats` | 群活跃卡：7 天发言榜 + 24 小时分布 | 当天 + 群 |
| `help` | 纯文字帮助 | 无 |

**生成耗时**：每张卡片底部都有「生成于 MM-DD HH:MM · N ms」。
N 是**首次画这张图**的耗时（含下载宣传图），当天再问同一个指令会直接复用文件，
所以底部仍是首次生成时的时间/耗时——这是对的，不是 bug。
| `watch` | 写入 `data\furcon_watch.json`，每天定时播报 | — |

缓存文件名：`data\furcons_cards\YYYYMMDD_<key>_<hash>.png`
末尾的 8 位哈希是必需的——中文会被过滤成下划线，不加哈希「江苏」和「上海」
会撞到同一个文件名。


### 今日人品（jrrp）算法

```
seed = sha256(f"{QQ号}|{YYYYMMDD}")
jrrp = int(seed[:8], 16) % 101        # 0 ~ 100
提示语 = FORTUNE_TIPS[int(seed[8:12], 16) % len(FORTUNE_TIPS)]
```

- **同一 QQ + 同一天 → 结果恒定**，刷新多少次都一样
- 换一天自动重算
- 不同 QQ 相互独立，平均分约 50

等级划分：

| 分数 | 等级 | 占比（2000 次抽样） |
|---|---|---|
| 90~100 | 大吉 | 11% |
| 75~89 | 中吉 | 15% |
| 60~74 | 小吉 | 15% |
| 40~59 | 平 | 20% |
| 20~39 | 小凶 | 20% |
| 0~19 | 凶 | 20% |

要调口味改 `fortune_of()` 里的阈值即可，不用动别处。

## 6. 怎么加/改词

**加别名**（最常见）：找到对应 key 那一行，往正则里加 `|新词`。

```python
# 原来的
("next", re.compile(r"(下次展|下一次展|下一场)")),

# 加一个"下回展"
("next", re.compile(r"(下次展|下一次展|下一场|下回展)")),
```

**加新功能**：
1. 在 `COMMANDS` 里加一行 `(key, re.compile(...))`，**放在更宽泛的规则之前**
2. 在 `handle()` 里加 `if key == "你的key":` 分支
3. 在 `HELP_TEXT` 里加一行说明
4. 重启

**注意顺序**：`COMMANDS` 是从上往下匹配的，第一个命中就返回。
比如 `city_past` 必须排在 `city_next` 前面，否则"哪里上次展"可能被 `city_next` 的宽泛规则吃掉。

## 9. 已知行为

- **斜杠被剥掉也能识别**：AstrBot 把 `/` 当唤醒前缀，`message_str` 里没有斜杠，
  所以插件读的是 `event.message_obj.raw_message` 的原始文本
- **斜杠消息绝不进模型**：peer 插件的闸门会拦截并 `stop_event`，
  所以打错命令只会没反应，不会让模型乱答
- **纯文字不触发**：`近期展` 不带斜杠也不喊名字时，按普通聊天处理
