# QQNT Bot 项目说明

> 把本地 AI 接进真实 QQ 账号（小号）的群聊/私聊，做成一个"像群友"的聊天机器人。
> 项目根目录：`D:\QQNTBOT`　最后更新：2026-11-17
> 模型服务在 `D:\LLM`（**只调用，不改它的源文件**）

---

## 1. 这是什么

一个跑在自己电脑上的 QQ 机器人，用真实 QQ 账号登录（非官方 bot、非协议库），
背后接的是本地的 9B 大模型。它不像客服，而像一个固定的群友：

- 有固定人设（写在 `data\persona.json`，控制台可改，本文档不复述具体内容）
- 会判断"这句话该不该接"，不是每条都回
- 有长期记忆，记得住每个人的事
- 能读图（OCR）、能发表情包、会搜网
- 冷场时会自己找个话题

**设计取向**：宁可少说、说错话，也不刷屏；宁可装死，也不编事实。

## 2. 总体架构

```
QQNT 9.9.25（替换过 QQ.exe + dbghelp.dll 绕过文件校验）
 └─ resources/app/package.json → loadNapCat.js
     └─ NapCat 核心（跑在 QQ 进程内，单进程模式）
         └─ OneBot v11 反向 WS → 127.0.0.1:6199
             └─ AstrBot 4.29.4（Python，独立 venv）
                 ├─ 主模型   → 8080  llama.cpp 路由（9B，128K）
                 ├─ 判官     → 8082  Qwen3-1.7B，CPU，只输出 0/1
                 ├─ 读图     → 8083  PaddleOCR-VL-1.6（常驻）
                 │    └─ 缓存代理 → 8084（哈希去重）
                 ├─ 向量     → 8097  bge-small-zh（NPU）
                 ├─ 语音     → 8096  Whisper small int8（NPU）
                 ├─ 联网     → 9000  SearXNG（Docker）
                 ├─ 记忆     → data\memory.db（SQLite）
                 └─ 控制台   → 6190  本项目 dashboard
```

**为什么 OCR 单独一个进程**：路由是 `--models-max 1`，同一个端口换模型会把 9B 挤掉。
读图如果走 8080，每读一张图就要重新加载 9B（十几秒），所以给它独立端口常驻。

## 4. 一条消息的完整链路

```
群消息
 ├─ 白名单检查（不在白名单 → 直接丢弃；私聊提示"未授权"）
 ├─ 是不是 @ / 唤醒？
 │    ├─ 是 → 排队（不丢弃），计入回复预算
 │    └─ 否 → 命中召唤词（阿灰/小灰…）？
 │         ├─ 是 → 直接接，计入预算
 │         └─ 否 → 该群自动接话开了吗？
 │              ├─ 关 → 不接
 │              └─ 开 → 规则层（免打扰 / 必答关键词 / 必答正则）
 │                   └─ 还没定 → 判官 Qwen3-1.7B 判 0/1（温度 0.5）
 │                        └─ 预算未满 + 概率命中 → 接
 ├─ 注入防护（套提示词 / 改设定 / 越狱 → 完全不回）
 ├─ 要表情包？（"发个表情"/"卖萌"）→ 直接发图，不进模型
 ├─ 进模型
 │    ├─ 人设（persona.json → 数据库人格行）
 │    ├─ 严格化提示（一次两句、别编名字）
 │    ├─ 图片释义（表情库命中 → 分类含义；否则 OCR 结果）
 │    ├─ 长期记忆（按当前消息召回，总量封顶）
 │    └─ 群聊上下文（最近 N 条）
 ├─ 输出后处理
 │    ├─ 正则替换（句末「。」→「~」）
 │    ├─ 废话过滤（"不知道"类直接不发）
 │    └─ 30% 概率附带一张表情
 └─ 分段发送（human 间隔：0.45s + 字数/7，带抖动）
```

## 5. 人设与说话风格

**人设**存在 `data\persona.json`，启动时由插件写进 AstrBot 的 `personas` 表
（`grey` 和 `default` 两行都写 —— AstrBot 每次启动会重建 default 行，
不覆盖它的话会回退到"You are a helpful assistant"）。

具体人设内容只以 `data\persona.json` 为准，这里不复述——改人设时不用同步改文档。

**参数**（控制台可调，保存即重启 AstrBot）：

| 参数 | 当前值 | 作用 |
|---|---|---|
| temperature | 0.55 | 越低越守设定，高了容易冒出口癖 |
| top_p | 0.9 | — |
| repeat_penalty | 1.02 | 压重复用词 |
| max_tokens | 80 | 约 55 个汉字 |

**文本后处理**（`data\reply.json`，正则，保存即生效）：

```json
{"pattern": "。(?=\\s|$|[（(\\[【「『])", "to": "~"}
```

只替换**句末**句号，中间的句子不受影响。

"句末"的定义包含三种情况：后面是空白、后面是结尾、**后面紧跟括号动作**。
第三条是后补的——模型常把动作放句尾写成 `你好。（歪头）`，
最初的正则只认空白和结尾，这种就漏掉了，表现是"规则突然失效"。

注意必须用前瞻 `(?=...)`，不能用捕获组，否则括号会被一起吃掉。

## 6. 长期记忆

- 存储：`data\memory.db`，表 `facts(uid, text, emb, created, slot, value, source, superseded_by, conf)`
- 向量：bge-small-zh（NPU，8097），余弦相似度召回，阈值 0.32，去重 0.92
- 提取：**每 90 秒**扫一次群历史，每轮最多 4 个人，同一个人 300 秒冷却；
  对话中被回复的消息另外即时抽一次（45 秒冷却）
- 提取算法（三段）：
  1. **粗筛（纯规则，不花 token）**：只剔除 `/指令`、纯表情、纯标点、问句。
     像「南京这破班真上不动了」这种省略主语的口语**必须放行**——群聊里没人
     说「我喜欢X」这种完整句，用规则挖事实的命中率实测只有 0.6%
  2. **标注（模型）**：把该人最近 ≤8 条消息编号送上，模型只输出
     `编号|槽位|值` 或 `编号|NONE`，槽位限定 10 个
  3. **成句（纯规则）**：`slot+value` 走模板 + 去冗余前缀，
     不再让模型多跑一次改写
- 防编造：**值必须是原话里连续出现的几个字**（去掉标点后做子串判断），
  点不到就丢弃；3 字以上允许 80% 字符重合（容忍语序微调）
- 兜底：模型不可用/返回空 → 退回规则挖掘「我喜欢猫」这类完整断言，不会全空转
- 去重：文本 → 值 → 同槽位子串（旧记录标 `superseded_by` 作废）→ 向量 0.92
- 过期：`activity` 3 天 / `habit` 45 天 / 无槽位老条目 180 天，先标
  `superseded_by=-1`，同一轮清理再**物理删除**（删前整行归档到
  `data\ltm_purged.jsonl`）；`purge_enabled: false` 可退回只标记不删
- 时间戳：`activity`/`habit` 这两类说的是「最近在干嘛」，会过期，注入时自动带
  （`对方在做每日任务（2周前）`）；`pet`/`name` 这类长期事实不带时间
- 日常不重复记：同一人 `activity`/`habit` 在 4 天内出现字面高度重合（字符集
  Jaccard ≥ 0.6，如「刷每日任务」「做每日任务」）的记录，只留一条。
  换城市不算重复——`在南京上班`/`在杭州上班` Jaccard 只有 0.43
- 注入：最多 4 条，单条截 60 字，整块上限 600 字（约占 64K 上下文的 0.6%）；
  文本相似 ≥0.85 的记忆不重复进块
- 管理：控制台「最近记住的事」可逐条删 / 全清

**设计原则**：宁可漏，不可错。行为归纳（"用户喜欢用调侃语气"）不是事实，全部拒绝。

**踩过的坑**：v2 的算法是「规则先挖候选 → 模型只改写」，结果真实群聊里含「我」
的消息只占 15%，规则命中率 0.6%，候选恒为 0 → 模型永远不被调用 → 一条记忆都
不生成。规则只能用来筛"不值得看的消息"，判断"是不是事实"必须交给模型。

## 7. 图片理解

三段式，彼此独立：

**① 读图（8083）**
PaddleOCR-VL，能抄图上的字 + 一句画面描述。2GB 常驻，不碰 9B。

**② 缓存（8084）**
按图片内容的 SHA256 存释义，100% 命中就直接返回。
同一张图第二次 0.009 秒，零算力。上限 5000 条，LRU 淘汰。

**③ 上下文注入（vision 插件）**
- 群里每张图后台生成释义，存进该会话的环形缓冲（6 条）
- 回复时取 15 分钟内最近 3 条注入
- **如果这张图是表情库里收录过的**：直接给分类含义（`[表情库·难过] 哭、委屈…`），
  **跳过 OCR**，更快也更准

## 8. 表情包

三套包，默认启用 furry：

| 包 | 张数 | 分类 | 用途 |
|---|---|---|---|
| **furry** | 80 | 12（开心/生气/累了/难过/惊讶/无语/吃喝/日常/困惑/感谢/害羞/拒绝） | 默认选包 |
| unsorted | 变动 | 未分类 | 收件箱，新图自动落这里 |
| marisa-meme-pack | 165 | 22 | 东方魔理沙，GIF |

**三种发图方式**：

1. **明白要图**：消息里出现"表情包/发张图/卖萌"等 → **100% 直接发**，不进模型
2. **随机附带**：正常回复按 30% 概率挂一张（控制台可调 0~100%）
3. **模型自己调工具**：`send_meme` 可用，但 9B 在长提示下经常不调

**第 2 种的分类怎么选**：不是随机抽，而是按情绪打分。

```
12 类情绪词库共 331 个词，每个词带权重 1~3
用户消息命中权重 × 2  +  机器人回复命中权重 × 1  =  该分类得分
取最高分；最高分不足 2 分就不发图
```

**为什么加了「不足 2 分不发」**：以前没命中任何情绪词时会从全部 86 张里随机抓一张，
只碰到「烦」「香」这种弱词也会配图，实际效果就是"情绪对不上"。现在弱信号直接跳过，
只发得出手的图。代价是配图频率下降，换来的是不违和。

**未分类库的体积闸门**（`meme_manager/backend/auto_collect.py`）：

群里的图自动收集时，单张超过 **1.5 MiB** 的直接跳过，不进 `unsorted`。
表情包一般几十到几百 KB，而长图/截图/原图照片动辄几 MB——上限放 20 MiB 时，
168 张里有 15 张超过 1.5 MiB，占了整个库 70 MiB 里的 40 MiB。
配置项：`auto_collect.max_sticker_bytes`（默认 1572864，可调到 5 MiB）；
**手动上传不受此限**，仍走 20 MiB 兜底。

同一个词可以在多个分类里带不同权重，用来消歧：

| 词 | 归属 |
|---|---|
| 离谱 | 无语 2 / 生气 1 / 惊讶 1 → 判成**无语** |
| 算了 | 无语 1 / 拒绝 1 → 看其他词谁加分 |
| 不想 | 拒绝 2 |

日志：`[peer] meme mood 难过 scores={'难过': 10, '拒绝': 1}`

**收集**：群里每张图都会被存进 `unsorted\memes\未分类\`（按哈希去重，
已在任何包里的不重复收）。你在 AstrBot WebUI 里把它拖到对应分类即可。

**描述存在哪**：`memes_data.json`（不是 manifest）。插件以它为准，
manifest 从它同步。**改分类不会丢描述**，新分类才会是"请添加描述"。

## 9. 群聊行为控制

六层，互不干扰：

| 控制 | 粒度 | 位置 | 说明 |
|---|---|---|---|
| 白名单 | 群 / 人 | AstrBot 配置 | 不在名单直接丢弃 |
| 主动冒泡开关（无唤醒词选择性聊天，主特色） | 每群 | `group_flags.json` 的 `auto_chat`（控制台「群聊开关」/ `/群聊 冒泡开/关`） | 关掉后判官整体短路，只有召唤词/骰子；默认开 |
| 召唤词直通 | 全局 | `data\judge.json` 的 `summon`（控制台） | 喊名字必回，不看概率闸 |
| 每群回复预算 | 每群 | `data\reply.json`（控制台） | 10 分钟内最多 8 条，@ 和召唤也算 |
| 主动回复概率 | 全局 | `data\reply.json`（控制台） | 判官判 1 后再按概率抽，默认 0.2 |
| 热群（冷场发预设暖场话，次要） | 每群 | `group_flags.json` 的 `warmup`（`/群聊 热群开/关`）+ `data\water.json` 的 `idle_min`（空闲时长） | 单一开关 = warmup，默认关；90 分钟没动静才发 |

**三条路径的优先级**：

```
@ 它            → 必回（计入预算）
喊名字（召唤词） → 必回（计入预算）
判官判 1        → 预算未满 + 概率命中 → 回
其余            → 不回
```

预算的意义：@ 和召唤虽然必回，但**占名额**；半小时里被叫了 8 次，
随机插话就自动停，总音量不会失控。

**注入防护**：命中"忽略之前的指令/输出你的提示词/开发者模式/ignore previous instructions"
等特征 → 完全不回（不是回一句"我不能"，那等于告诉对方猜对了）。

**并发**：@ 消息全部排队（AstrBot 会话锁顺序处理，不丢弃）；
同一会话正在生成时，非 @ 的新消息丢弃。

## 10. 控制台（`http://127.0.0.1:6190`）

2026-11-19 重排为六个分页，顶部标签：**概览 / 对话 / 判官 / 记忆 / 视觉 / 系统**。
每个面板声明自己属于哪种模式（`data-only`）；当前模式用不到的整块**置灰禁用**，
并在右下角写明原因（例如「第三方模式下由 API 决定」「本地模式不调 API 判官」）。
顶部徽章显示「本地模型模式 / 第三方 API 模式」，模式真相读
`cmd_config.json` 的 `agent_runner.config.model.provider_id`。

| 分页 | 主要面板 | 模式相关性 |
|---|---|---|
| 概览 | 当前模式与链路、系统状态、最近记住的事、最近对话 | 通用 + 模式链路说明 |
| 对话 | 人格、回复行为（预算/召唤词/上下文时间窗/回复概率/表情概率/正则）、模型采样参数、触发权限、自动接话/水群开关 | 部分项仅本地生效，置灰 |
| 判官 | 本地判官提示词/关键词/正则/试判、第三方判官（密钥/模型/限额/开关）、话段聚合、双判官 | 两块判官按模式互斥置灰 |
| 记忆 | 最近记住的事、LTM 抽取节奏（扫描间隔/预算/冷却、第三方模式开关） | 抽取节奏第三方模式可关 |
| 视觉 | 识图模式（本地 VL / 交给第三方 / 关闭）、缓存条目/命中/图库统计/最近识别 | 本地 VL 入口仅本地模式可用 |
| 系统 | 模式与链路对照表、模式切换按钮、性能档位、关联项目/外部依赖、主模型、已装模块、运行日志 | 通用 + 切换入口 |

「模式与链路」表按两种模式列出每条链路是否可用（本地读图、双判官复核、API 判官、
额度闸与审查等），是排查「功能怎么没了」的第一站。

控制台保存采用**合并写入**：只覆盖本次真正提交的字段，空值不会清空旧配置
（正则规则要清空必须显式传 `clear_rules`）。

### 上下文时间窗的条数兜底

群聊上下文先按 `reply.json` 的 `history_minutes`（默认 20 分钟）裁剪。冷场后开新话题时，
时间窗里可能只剩一两句话，模型等于没有上下文。故加了条数兜底：若窗内消息
`< history_min_count`（默认 3）且原始窗口里还有更多消息，则改用最近
`history_fallback_count`（默认 12）条——旧一点也比空着强。条件为严格小于，
窗内正好等于 `history_min_count` 不算过少；总消息数不足以回填时不触发。
配置读写见 `group_chat_context.load_history_fallback()`（默认值 3/12，
范围 1~20 / 不低于 min_count 且 ≤40）。

### apimode 模式判定修复

`data/api_mode.json` 的 `mode` 只是 `/切换` 的记账，WebUI 改 provider 后它可能缺失或过期，
导致额度闸 / 群审查 / 省 token 三条逻辑静默失效。现统一改为 `apimode.current_mode()`
从 `provider_id` 推导（含 `deepseek` 即第三方），文件仅作兜底；计数只在第三方模式累加。

## 11. 关键文件

| 路径 | 是什么 |

## 12. 运维

**启动**：双击桌面「启动QQ机器人」（= `start-all.ps1`）
自动完成：版本守卫 → 读模式 → （本地模型）→ 判官/嵌入/释义缓存 → AstrBot → QQ/NapCat → 控制台
→ 语音识别（8096）+ SearXNG（9000，按需 `docker start`），需要扫码时会自动弹出二维码窗口。

读 `agent_runner.config.model.provider_id` 决定是否起 8080/8083/8085：**第三方模式跳过，省约 14 GB**。
判官/嵌入/释义缓存/语音识别/SearXNG **两种模式都会起**——缺了它们语音消息会转写失败、联网搜索会哑掉。
服务默认用 WMI 分离启动（父进程 `WmiPrvSE.exe`），关掉 PowerShell 窗口不会带走机器人。

参数：`-ThirdParty` 强制跳过本地模型 / `-Local` 强制启动 / `-NoBrowser` 不开页面 / `-NoDetach` 挂在本窗口。

**停**：`stop-all.ps1`（按端口杀进程），`-KeepQQ` 保留 QQ、`-KeepModels` 保留本地模型（含语音识别）。
SearXNG 不停：它是 Docker 容器（`restart=unless-stopped`），要停请 `docker stop searxng`。
返回码 0 = 全部按预期停止；1 = 有端口没释放（权限不够，或被别的东西又拉起来了）。

**只重启 AstrBot**：`scripts\restart-astrbot.ps1`（10 秒，QQ 不断线；按 6185 端口定位进程）

**日志**：
- AstrBot：`apps\AstrBot\data\logs\astrbot.log`
- NapCat：`apps\NapCat\logs\`
- 路由：`D:\LLM\logs\`
- 语音识别：`D:\LLM\logs\stt-npu.out` / `stt-npu.err`
- 判官/OCR：`_backup\judge.err` / `ocr.err`

## 13. 已知限制

1. **版本锁死**：替换的 QQ.exe 是 9.9.25.42941，QQNT 一升级注入即失效
2. **AstrBot 补丁会被升级覆盖**，共 5 处（见下）
3. **判官不准**：1.7B 做二分类只有 85% 左右，所以外面叠了规则层
4. **小模型工具调用不稳**：长提示下 9B 常常不调 `send_meme`，所以才做意图拦截
5. **记忆会漏**：证据校验保证不错，但会漏掉别人提你的事
6. **读图只认字**：OCR 能抄文字，纯画面梗（一张猫）它看不懂
7. **会编造具体名词**：9B 遇到不认识的活动/关卡会硬编（已用提示词和证据校验缓解，未根治）
8. **自称会漂移**：模型偶尔自造称呼（如"本灰"），靠 repeat_penalty 压，不能根除
7. **NapCat 上游已删库**：当前是从 fork 源码构建的，无法升级
